# AGENTS.md

Правила для ИИ-агентов, которые работают в этом репозитории. Люди читают [README.md](README.md) и [docs/](docs/README.md); агентам стоит прочитать оба, но жёсткие правила собраны здесь.

Проект: **reDTF** — неофициальный клиент DTF. Статичное SPA на SvelteKit 3 и Svelte 5, без сервера. Язык комментариев, коммитов-описаний в доках и общения — русский; идентификаторы — английские. Отступы — табы.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер. Для превью: `.claude/launch.json` → `redtf-dev`, порт 5173 (если занят, сервер берёт другой) |
| `npm test` | юнит-тесты (vitest) |
| `npm run check` | `svelte-kit sync` + `svelte-check` |
| `npm run build` | статическая сборка в `build/` |

`svelte-check` сейчас показывает около 50 старых ошибок (в основном в заглушках `classic` и `modern` и из-за `$props<…>()`). **Новых быть не должно**: сохраните вывод до правок и сравните после.

## Карта кода

| Путь | За что отвечает | Подробнее |
| --- | --- | --- |
| `src/routes/` | маршруты и корневой `+layout.svelte` (рисует оверлеи, ставит тему) | [navigation](docs/architecture/navigation.md) |
| `src/lib/navigation.ts`, `src/lib/feed.svelte.ts` | открытие и закрытие оверлеев, лента в адресе | [navigation](docs/architecture/navigation.md) |
| `src/lib/themes/` | реестр тем, `ThemeLoader`, контракт компонентов, сами темы | [themes](docs/architecture/themes.md) |
| `src/lib/components/` | общие компоненты (рендер блоков, комментарии, редактор, экран настроек) | [settings](docs/architecture/settings.md) |
| `src/lib/storage/` | всё, что хранится в localStorage | [storage](docs/architecture/storage.md) |
| `src/lib/api/` | фасад `api`, провайдеры, подключаемые источники | [api](docs/architecture/api.md), [data-sources](docs/architecture/data-sources/README.md) |

Рядом лежат отдельные репозитории: `reDTF-proxy` (CORS-прокси для входа), `reDTF-html` (старый статичный макет, **не эталон**).

## Жёсткие правила

1. **Без SSR и серверного кода.** `ssr = false`, адаптер `adapter-static`. Не добавлять `+page.server.ts` и `+server.ts`. Единственное исключение — `routes/api/version.json/+server.ts`, он пререндерится в статический файл.
2. **Данные только через фасад.** UI вызывает `api.getPosts()` и подобные из `src/lib/api/index.svelte.ts`. Не импортировать провайдеры (`providers/dtf`, `providers/source`) в компоненты. Ошибки сети превращаются в `Error` с понятным текстом внутри провайдеров.
3. **Темы только через `ThemeLoader`.** Компоненты темы лежат в корне `src/lib/themes/<id>/`, у каждой темы есть `theme.ts` (манифест). Пропсы описаны в `themes/contract.ts`. Не вставлять разметку конкретной темы в общие компоненты и маршруты.
4. **Хранилище только через `persistedState`** и только в слоях `settings`, `theme`, `secrets`, `data`, `cache` (ключ `redtf:<слой>:<имя>`). Прямой `localStorage` запрещён. Исключение — зарезервированные `redtf:setup:*` для будущего мастера первой настройки (их читает `app.html`).
5. **Навигация только через `$lib/navigation`.** Открывать оверлеи через `openOverlay`, закрывать через `closeOverlay`, ленту менять через `openFeedTab`. Не вызывать `pushState`, `history.back()` и не слать события через `window`.
6. **Нет легаси и миграций.** Проект до релиза, пользователей нет. При изменении формата данных поднимайте `version` у `persistedState` (старые данные отбросятся) и **не пишите миграции и обратную совместимость**. Удаляя код, удаляйте его целиком, без заглушек.
7. **Svelte 5, только руны.** `$state`, `$derived`, `$props`, `onclick={…}`, `{#snippet}`/`{@render}`, `{@attach}`. Состояние, общее между компонентами, — модули `*.svelte.ts` (объект с геттерами или класс), не сторы. Запись в состояние внутри `$effect` — крайняя мера (см. «Подводные камни»).
8. **SvelteKit 3.** `$app/env` вместо `$app/environment`, `page` из `$app/state` (`$app/stores` удалён), `goto(url, { shallow: true, state })` вместо `pushState`, `replace` вместо `replaceState`, `reset: false` вместо `keepFocus`. Пути всегда через `resolve()` из `$app/paths` (на GitHub Pages есть `base`).
9. **Новые зависимости только с разрешения** владельца: важен размер бандла. Тяжёлое грузится через `import()`.
10. **Стили.** Обычный CSS в компонентах, без Tailwind. Глобально только `app.css` и `theme.css` темы. Цвета и размеры темы — CSS-переменные.
11. **Секреты и данные пользователя** не писать в логи и в URL. Токены DTF уходят только на `api.dtf.ru` и на прокси из настроек, токены источников — только на их домены.

Стиль «ленивого senior» (минимум кода, без лишних абстракций, у нетривиальной логики один тест) описан в [.agents/rules/ponytail.md](.agents/rules/ponytail.md) и обязателен.

## Подводные камни

- **`$effect`, который пишет в настройки, может зациклиться**: запись меняет состояние, от которого зависит рендер, рендер заново монтирует компонент и снова запускает эффект. Писать настройки нужно из обработчиков (`onchange`, `onclick`) или через `bind:value={getter, setter}`. `persistedState.patch` сам читает значение без подписки, но это не отменяет правило.
- **В vitest `$effect` не выполняется** (Svelte собирается в серверном режиме). Логику, которую нужно тестировать, держите вне эффектов.
- **Dev-сервер ломается** после массовых правок и после `svelte-kit sync` под ним: страница висит на спиннерах или 404 на `.svelte-kit/…`. Лечится перезапуском превью (`preview_stop` → `preview_start`).
- **`classic` и `modern` — временные заглушки**, их удалит владелец. Не развивать, не чинить сверх необходимого, не копировать из них паттерны.
- **Скриншоты браузера** не рисуются, если окно приложения скрыто. Проверяйте вёрстку числами (`getBoundingClientRect`, `scrollWidth`) или текстом страницы.
- **Прокси.** `VITE_AUTH_PROXY_URL` задаётся в `.env` (пример в `.env.example`) и в переменных репозитория для CI. Зашитого адреса в коде нет, и добавлять его не нужно.
- **Правки вне `src/`.** `reDTF-proxy` и `reDTF-html` — другие репозитории: без отдельной просьбы не менять.

## Git

Рабочая ветка `dev`. Коммитьте по логическим шагам, короткими английскими фразами в повелительном наклонении (`Add …`, `Fix …`), без строк об авторстве. Не пушить и не открывать PR без просьбы владельца: пока локальные коммиты, исправления дозволяется докидывать в последний коммит.

Один коммит — одна область или одна логическая фича (слой API, примитивы темы, пост, комментарии, профиль, уведомления…). Не смешивайте в нём несколько фич и не переписывайте один и тот же элемент в нескольких коммитах подряд: пока не запушено, доработку элемента вносите в коммит, где он появился, а не новым «Fix …».

Если цепочка незапушенных коммитов получилась смешанной, перед пушем перегруппируйте её на отдельной ветке или в `git worktree` (резервная ветка у `dev` обязательна) и докажите, что ничего не потеряно:
1. итоговое дерево совпадает с исходным: `git rev-parse HEAD^{tree}` до и после (или `git diff <backup> HEAD` пуст);
2. каждый промежуточный коммит собирается: `npm run check` не хуже базы, `npm test` проходит;
3. только после этого переносите `dev` (`git reset --hard`), резервную ветку оставляйте до пуша.
Коммиты подписываются ключом: каждый ждёт касания, поэтому в одном вызове не делайте их пачкой с коротким таймаутом.

## Тема `dtf2022` (`src/lib/themes/dtf2022`)

Цель — совпадение с DTF начала 2023 года на 99.9%, особенно на мобильном.

- **Эталон — архив DTF**, а не `reDTF-html` (в нём часть значений придумана). Ссылки и способ измерений: см. ниже.
- **Новые элементы не добавлять** без согласования. Чего в теме пока нет (поиск и «Создать» в шапке, «Вакансии» и «Рейтинг DTF» в сайдбаре, виджеты, кнопка подписки в профиле), — перечислять и спрашивать.
- Стили изолированы в компонентах; глобально только `theme.css` (шрифт и токены).
- Брейкпоинты оригинала: левая колонка ≥860px, правая (320px) ≥1180px, мобильная панель ≤719px, `l-island-a` с отступами 20px (16px до 639px), колонка текста поста 600px (640px от 1560px). На страницах профиля правой колонки нет.

### Эпохи оформления

Вид оценок выбирается настройкой темы `votes` (описана в `dtf2022/theme.ts`, читается через `themeSettings.votes`):
`rating` — стрелки осени 2022, `likes` — лайк/дизлайк начала 2023 (по умолчанию), `reactions` — как сейчас.
Новые отличия эпох вешать на этот же переключатель.

### Как сверять с оригиналом

1. `.claude/launch.json` → сервер `redtf-dev` (порт 5173).
2. Во встроенном браузере открыть архивную страницу (`web.archive.org/web/<дата>mp_/https://dtf.ru/...`), удалить панель Wayback (`#wm-ipp-base`, `#wm-ipp`), выставить ширину 1280 и 390 у обеих вкладок.
3. Снять через JS `getBoundingClientRect()` и computed-стили элементов и сравнить. Оригинальный CSS читается из `document.styleSheets` (правила и `@media`) — так находить брейкпоинты, а не угадывать.

Эталонные страницы: лента `20230228202828`, пост `20230301025808` (`/games/1657264-...`), профиль `20230314185036` (`/u/120658-dzhamil-mahmutov/entries`), раздел `20230314185028` (`/science`), стрелки 2022 — `20220903095538` и `20220910200512`.
