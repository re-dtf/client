# 0004. Оверлеи на shallow routing и один модуль навигации

Статус: принято
Дата: 2026-11-01

## Контекст

Посты и профили открываются поверх ленты, чтобы она не теряла прокрутку и подгруженные посты. Для этого использовался `pushState` из SvelteKit, но вызовы были размазаны по компонентам: классические темы собирали состояние вручную, были события `window` (`switchFeed`, `refreshFeed`), закрытие через `history.back()` в семи местах, `/write` вручную вызывал `history.pushState` с внутренней структурой SvelteKit. В SvelteKit 3 `pushState` и `replaceState` объявлены устаревшими (вместо них `goto(url, { shallow, state })`), а `$app/stores` удалён.

## Решение

- Оверлей — типизированная запись в `page.state.overlays` (`App.OverlayData`, `App.OverlayState`).
- Вся работа в `src/lib/navigation.ts`: `openOverlay`, `closeOverlay`, `openPost`, `openProfile`, `openFeed`. Способ показа (`page` или `modal`) и адрес выводятся из типа.
- Реализация на `goto(url, { shallow: true, state })`.
- Корневой layout рисует стек одним сниппетом.
- Выбранная лента хранится в адресе (`/?feed=new`), а не в локальном состоянии страницы и не в событиях. Обновление ленты — счётчик в `feed.svelte.ts`.
- У каждого оверлея есть и обычный маршрут для прямой ссылки.

## Последствия

- Новый оверлей — это тип, адрес, способ показа и ветка в layout: TypeScript подскажет, что забыто.
- На ленту можно дать ссылку, кнопка «Назад» возвращает на прежнюю ленту.
- Состояние оверлеев не переживает обновление страницы (`persistState` не включён): адрес открывается как обычная страница. Это осознанно: сохранённое состояние оверлеев после перезагрузки показало бы устаревшие данные.
- Код тем не знает про внутреннее устройство истории: он вызывает функции навигации.
