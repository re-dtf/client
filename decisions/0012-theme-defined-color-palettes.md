# 0012. Цветовые палитры определяются темой

Статус: принято
Дата: 2026-11-09

## Контекст

Фиксированная пара светлого и тёмного оформления ограничивает темы: им могут понадобиться разные тёмные варианты или дополнительные цветовые сочетания. Глобальный выбор схемы не позволяет запоминать разные предпочтения для разных тем. Отдельная логика начального HTML рискует расходиться с приложением.

## Решение

Тема объявляет именованные палитры и соответствие двух системных режимов своим палитрам. Каждая палитра указывает базовый режим светлого или тёмного оформления для общих и системных элементов. CSS темы задаёт конкретные цвета.

Форк наследует весь набор, пока не объявит собственный. Частичного слияния нет: замена списка отдельно от системных соответствий могла бы оставить ссылки на отсутствующие палитры.

Выбор хранится в настройках конкретной темы. Системный выбор — отдельное зарезервированное значение. Неизвестный идентификатор разрешается в палитру по умолчанию без записи из эффектов. Старый глобальный формат удаляется с повышением версии общих настроек, без миграции.

Синхронный запуск собирается из тех же манифестов, функции чтения хранилища и функций выбора и применения палитры. Полученный скрипт встраивается в HTML-шаблон на этапе сборки; сервер приложению не нужен.

## Последствия

Новая палитра добавляется внутри темы. Общие компоненты продолжают использовать CSS-токены и базовый режим, не зная имён палитр. Окно настроек предоставляет переопределяемые токены для своих поверхностей.

Сборка дополнительно формирует ранний скрипт. Манифесты тем участвуют в раннем запуске и должны оставаться лёгкими и не зависеть от состояния приложения. Ручной список цветов в HTML и отдельный кэш разрешённой палитры не нужны.
