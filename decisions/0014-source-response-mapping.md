# 0014. Декларативное сопоставление ответов и неразрушающее восстановление данных

Статус: принято
Дата: 2026-11-11

## Контекст

Подключение сторонних публичных сервисов (включая архивы комментариев сообщества) сталкивается с тем, что их API не следует внутренней схеме reDTF:
- Ответы упаковываются в произвольные конверты (`{ status: "ok", data: [...] }`), идентификаторы могут приходить строками, даты — в секундах Unix, а медиа — ссылками или UUID Leonardo.
- Режим полной замены (`mutate:comments:replace`) для архивов вреден: архив часто хранит только первую замеченную версию комментария. Замена живых комментариев на архивные данные приводила бы к откату недавних правок у живых неудалённых комментариев и потере актуального состояния ветки.
- Сторонние архивы обычно не поддерживают постраничную пагинацию по курсору и отдают сохранённые данные поста целиком. Опрос такого сервера на каждом посте создавал бы избыточную нагрузку на волонтёрскую инфраструктуру.

## Решение

1. **Декларативное сопоставление ответов (`responseFormat: 'mapped'`)**:
   - Эндпоинты манифеста могут объявлять объект `mapping`, задающий путь к списку элементов (`items`), коды статусов отсутствия данных (`emptyStatuses`, например `[404]`), таймаут (`timeoutMs`) и сопоставление полей (`fields: { id, authorId, content, media }`).
   - Поддерживаются стандартные преобразования типов: `number`, `string`, `unixToIso`, `leonardoImage`. Поле `media` очищается всегда, независимо от заданного преобразования: иначе источник мог бы подсунуть внешние URL.
   - Доступ к полям ответа ограничен простой точечной навигацией и индексами массивов. Сегменты `__proto__`, `constructor`, `prototype` блокируются.
   - Текстовые поля очищаются от управляющих символов и скрытых маркеров направления письма Unicode (BiDi).

2. **Неразрушающее наложение (`mutate:comments:restore`)**:
   - Восстановленный контент не перезаписывает оригинальный объект комментария, а сохраняется в отдельном свойстве `comment.restored = { content, media, sourceId }`.
   - Проверяется совпадение автора (`authorId` из архива должен строго совпадать с `author.id` заглушки на DTF).
   - Неудалённые комментарии и живое дерево DTF остаются нетронутыми.

3. **Ленивый опрос и сессионный кэш**:
   - Источники, запрашивающие только восстановление, не опрашиваются вовсе, если на загруженной странице нет удалённых комментариев, удовлетворяющих настройке пользователя (`restoreScope`).
   - Непагинированные эндпоинты (`paged: false`) кэшируются на уровне сессии поста в оперативной памяти с объединением параллельных запросов (in-flight coalescing).

4. **Пользовательские настройки и оформление**:
   - Пользователь может настроить охват («Все удалённые» или «Только удалённые модератором») и способ показа (свёрнуто под заглушкой с кнопкой «Показать из архива» или развёрнуто сразу).
   - В теме `dtf2022` восстановленный комментарий помечается аккуратной меткой «из архива» в строке времени, а интерактивные действия (оценки, ответы, редактирование) блокируются.

## Последствия

- Сторонние API подключаются без написания императивного кода в клиенте.
- Живое дерево комментариев DTF остаётся нетронутым.
- Трафик к сторонним серверам минимален: посты без удалений архив не беспокоят, остальные кэшируются.
- В клиент не добавлялись сторонние библиотеки (JSONPath), размер бандла не увеличился.
