# Архитектурные решения

Короткие записи о том, **почему** сделано так, как сделано (ADR, Architecture Decision Records). Код отвечает на вопрос «как», а эти записи нужны, чтобы через полгода не пересматривать решение вслепую и не ломать то, что делалось нарочно.

## Когда писать

Когда выбрали один из нескольких разумных путей, и по коду будет не понять почему. Не нужно писать про очевидное и про детали реализации.

## Как писать

Новый файл `NNNN-короткое-название.md`, следующий номер по порядку. Шаблон:

```md
# NNNN. Название решения

Статус: принято | заменено решением NNNN | отклонено
Дата: ГГГГ-ММ-ДД

## Контекст
Какая была задача и какие ограничения.

## Решение
Что делаем.

## Последствия
Что стало проще, что сложнее, от чего отказались. Какие варианты рассматривали и почему не выбрали.
```

Принятое решение не переписывают: если оно устарело, пишут новую запись и ставят в старой статус «заменено».
