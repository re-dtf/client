# Система Источников Данных (Data Sources) в reDTF

reDTF использует масштабируемую, декларативную систему подключения произвольных источников данных. Это позволяет клиенту объединять контент из официального API DTF с пользовательскими серверами (например, архивы удалённых комментариев, альтернативные системы реакций, сторонние ленты постов).

## Ключевые принципы

1. **Конфигурация, а не код**: Сторонние источники подключаются через JSON-манифесты (`redtf-source.json`), размещённые в Git-репозиториях. Исполняемый код сторонних разработчиков в клиент не загружается.
2. **Transparency First**: Все сетевые запросы выполняются непосредственно из браузера пользователя. Клиент никогда не передает основной токен DTF на сторонние серверы. Пользователь всегда может отследить сетевую активность в DevTools.
3. **Безопасные разрешения**: Разрешения запрашиваются *только* на мутирующие операции (отправка контента, визуальная подмена элементов). Запросы на чтение прозрачны и отображаются пользователю при добавлении источника.

## Архитектура клиента

Система интегрирована глубоко в архитектуру Svelte 5 приложения и состоит из следующих слоёв:

- **Манифесты и Реестр (`src/lib/api/sources/`)**: Отвечает за парсинг, валидацию и хранение манифестов сторонних источников. Включает реактивный `registry.svelte.ts` для управления состоянием источников.
- **Провайдер источника (`src/lib/api/providers/source.ts`)**: превращает манифест в набор методов (`getPosts`, `getComments`, …), выполняет декларативное преобразование форматов ответов (`response-mapping.ts`) для внешних API (`responseFormat: 'mapped'`) и проверяет, что источник вернул список, а не мусор.
- **Фасад API (`src/lib/api/index.svelte.ts`)**: Единая точка входа для UI-компонентов. Делает запросы к DTF и ко всем активным сторонним источникам, после чего сливает данные. Упавший источник не ломает остальные: причина пишется в консоль. Источники восстановления опрашиваются лениво (только при наличии удалённых комментариев на странице), а непагинированные ответы кэшируются на уровне поста.
- **Слияние данных (Merger)**: Объединяет данные (комментарии, посты) из нескольких источников. Поддерживает добавление (`append`), подмену (`replace`), неразрушающее восстановление удалённых заглушек (`restore`) с валидацией автора. Использует композитные ID (`sourceId_id`) для предотвращения коллизий.
- **Композитные ключи в UI**: Svelte-компоненты используют строковые ключи для рендеринга списков (`{#each}` блоки), что позволяет безопасно отображать смешанный контент на одном экране.

## Роутинг и Composite IDs

Каждый элемент данных (`Post`, `Comment`) размечается полем `sourceId`. 

- Официальный API DTF имеет `sourceId: 'dtf'`.
- Сторонние источники используют `id` из своего манифеста (например, `dtf-deleted-comments`).

При рендеринге интерфейса, клиент объединяет эти идентификаторы (`sourceId + '_' + id`), чтобы Svelte корректно отслеживал элементы в DOM. Маршрутизация обратных действий (например, лайк комментария) происходит на основе поля `sourceId` конкретного элемента.

## Механизмы авторизации

Система поддерживает 4 типа авторизации для сторонних источников:

1. `none`: Публичные API без авторизации.
2. `token_header`: Ручной ввод API-ключа пользователем в настройках.
3. `oauth2_pkce`: Стандартный OAuth2 (Authorization Code Flow with PKCE).
4. `bio_verification` (re:connect): Уникальный механизм авторизации, доказывающий владение аккаунтом DTF путём временной записи проверочного кода в раздел «О себе» (Bio) пользователя. Клиент автоматически генерирует код, временно обновляет профиль на DTF, сервер проверяет наличие кода, и профиль восстанавливается.

## Каталог источников

Каталог — один JSON-файл в отдельном репозитории, адрес задан в `api/sources/builtins.ts`. В нём `catalogVersion`, `lastUpdated` и список `sources`. У записи обязательны `id`, `name` и `manifestUrl`; необязательны `description`, `author`, `icon` (только `https`), `tags` и `verified` (проверен командой reDTF).

Клиент разбирает каталог в `api/sources/catalog.ts` и показывает только то, что можно отобразить: битые записи отбрасываются, проверенные идут первыми. Установка из каталога ничем не отличается от добавления по адресу: манифест загружается и проходит то же подтверждение разрешений. Источник считается установленным, если совпал адрес манифеста или `id`.

## Где что хранится

- Подключённые источники, их манифесты и выданные разрешения — `redtf:data:sources`.
- Токены источников — отдельно, `redtf:secrets:source-tokens` (по id источника, со сроком действия). Просроченные токены удаляются при запуске, токен удалённого источника — вместе с ним.
- Состояние проверки через «О себе» — `redtf:data:bio-cleanup`.
