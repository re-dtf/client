# План реализации системы Источников Данных (Task List) - Детализированный

В этом документе задача разбита на глубоко проработанные шаги с учётом текущей кодовой базы (Svelte 5 Runes, архитектуры API-фасада) и возможных подводных камней, включая сложные аспекты сети и реактивности.

Подготовка строгой типизации и реактивного хранилища.

- `[x]` **Шаг 1.1: Типы системы источников (`src/lib/api/sources/types.ts`)**
  - Описать `SourceManifest`, `SourceEndpoint`, `SourcePermission`, `SourceState` (как в плане).
  - Написать строгие Type Guards (например, `isSourceManifest(obj: any): obj is SourceManifest`) для валидации полей `manifestVersion`, `id`, `api.baseUrl` при загрузке.
- `[x]` **Шаг 1.2: Обновление базовых моделей (`src/lib/api/types.ts`)**
  - Добавить обязательное поле `sourceId: string` в интерфейсы `Post`, `Comment` и `CommentTreeItem`.
  - Добавить опциональные поля для UI: `isReplaced?: boolean`, `originalSourceId?: string` (если коммент подменён).
- `[x]` **Шаг 1.3: Адаптация DTF-провайдера (`src/lib/api/providers/dtf.ts`)**

## Фаза 3: Svelte Реактивность (Критический узел)
Исправление потенциальных проблем с коллизиями ID перед тем, как мы начнём сливать данные.

- `[ ]` **Шаг 3.1: Композитные ключи в UI-циклах**
  - Найти все `{#each}` блоки в темах (`classic/Comments.svelte`, `classic/EditorialNews.svelte`), которые используют `post.id` или `comment.id`.
  - Изменить их на композитный ключ: `{#each logic.comments as comment (comment.sourceId + '_' + comment.id)}`.
- `[ ]` **Шаг 3.2: Обновление `commentsLogic.svelte.ts`**
  - Изменить тип `allCommentsMap` на `Map<string, CommentTreeItem>`.
  - Передавать строковый композитный ID во всех методах.
  - *Предостережение: Использовать только ES6 `Map` (или `Object.create(null)`) для хранения и индексации composite ID, чтобы исключить уязвимости Prototype Pollution.*
- `[ ]` **Шаг 3.3: Обновление `buildTree` (`commentUtils.ts`)**
  - Изменить логику построения дерева: при поиске родителя по `replyTo` формировать ключ вида `${primarySourceId}_${replyTo}`.

## Фаза 4: Сетевой слой и Слияние (Мёрж)
Связываем данные из DTF с данными из добавленных манифестов (с учётом задержек, пагинации и ошибок).

- `[ ]` **Шаг 4.1: Фетчер, Таймауты и 401 Ошибки (`src/lib/api/sources/source-fetcher.ts`)**
  - **Таймауты:** Добавить `AbortController` с жестким таймаутом (3 секунды). Если сторонний сервер не ответил, запрос молча отменяется (не блокирует ленту).
  - **401 Unauthorized:** При получении 401 статуса перехватывать ошибку, обнулять `authToken` у источника в хранилище и выводить системный `console.warn` (чтобы UI не падал, а просто исключал сервер из выдачи до переавторизации).
- `[ ]` **Шаг 4.2: Мёржер постов (`src/lib/api/sources/merger.ts`)**
  - Обновить интерфейсы пагинации: курсор теперь должен быть `Record<string, { lastId: number; lastSortingValue: number }>` (составной курсор).
  - Сортировка объединённого массива по `createdAt`.
- `[ ]` **Шаг 4.3: Мёржер комментариев (`src/lib/api/sources/merger.ts`)**
  - *Режим Replace:* При замене оставлять оригинальный `replyTo` и `id` из DTF, добавлять `isReplaced: true`.
  - *Режим Append:* Добавление в конец массива (дерево построится само на шаге 3.3).
- `[ ]` **Шаг 4.4: Переписывание Фасада (`src/lib/api/index.svelte.ts`)**
  - В `getPosts` и `getComments`: запрашивать DTF + параллельно запрашивать активные источники через `Promise.allSettled`.
  - Распаковывать составной курсор и передавать каждому серверу свой. Собирать новые курсоры в единый объект на выходе.
