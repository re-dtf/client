# Навигация

Посты, профили, настройки, вход и редактор открываются **оверлеями** поверх ленты. Адрес при этом меняется (`/post/123`), кнопка «Назад» работает, а лента остаётся под оверлеем со своей прокруткой и подгруженными постами. Всю работу с оверлеями делает один модуль: `src/lib/navigation.ts`.

## Оверлей

Оверлей — запись в `page.state.overlays` (типы в `src/app.d.ts`):

```ts
type OverlayData =
	| { type: 'post'; data: { postId: number; sourceId: string; commentId?: number; focusNonce?: number; toComments?: boolean; anchor?: string } }
	| { type: 'profile'; data: { profileId: number | string } }
	| { type: 'settings'; data?: { page?: string; section?: string; solo?: boolean } }
	| { type: 'notifications' }
	| { type: 'tag'; data: { tag: string } }
	| { type: 'search'; data: { query: string } }
	| { type: 'drafts' }
	| { type: 'login' }
	| { type: 'editor'; data?: { postId?: number | null; repostId?: number } }
	| { type: 'lightbox'; data: { images: { uuid: string; width: number; height: number; type?: string }[]; index: number } };

type OverlayState = OverlayData & { id: string; presentation: 'page' | 'modal' | 'fullscreen' };
```

Способ показа (`presentation`) определяется типом:

- **`page`** (пост, профиль, уведомления, тег, поиск, черновики) — занимает место страницы. Лента под ним скрыта, но не размонтируется. Если открыто несколько, видим только верхний. Слой прямо под верхней страницей скрыт через `content-visibility: hidden` и выведен из потока: браузер хранит его раскладку, и закрытие страницы показывает его без пересчёта. Слои глубже скрыты через `display: none`, чтобы стек не держал раскладку каждого слоя.
- **`modal`** (настройки, вход, редактор) — окно поверх всего с подложкой, рисует `ModalShell`: подложка сразу, окно после загрузки его картинок, спиннер через 800 мс (см. [motion.md](motion.md)). Клик по подложке закрывает его.

- **`fullscreen`** (просмотр картинок) — оверлей сам рисует себя на весь экран, подложки у него нет.

Корневой `+layout.svelte` рисует стек: для каждого оверлея выбирает компонент по `type` (сниппет `overlayContent`), оборачивает по способу показа и запоминает прокрутку нижнего слоя.

## Функции `$lib/navigation`

| Функция | Что делает |
| --- | --- |
| `openOverlay(overlay)` | открыть оверлей: `openOverlay({ type: 'settings' })`. Адрес вычисляется по типу |
| `closeOverlay()` | закрыть верхний (шаг назад по истории, как кнопка «Назад») |
| `openLightbox(images, index, origin?)` | просмотр картинок (PhotoSwipe, грузится при первом открытии). Адрес не меняется, но это шаг истории: «Назад» закрывает просмотр. `origin` — миниатюра, из которой разворачивается кадр |
| `openPost(e, post)` | обработчик клика по ссылке на пост |
| `openProfile(e, id)` | то же для профиля |
| `openFeed(e)` | обработчик клика по логотипу и «Главной» |
| `openNotifications(e?)`, `openTag(tag, e?)`, `openSearch(query, e?)`, `openDrafts(e?)`, `openSettings(page?, solo?, e?)` | быстрые обработчики открытия соответствующих оверлеев |
| `openDtfUrl(url)` | открыть ссылку на DTF внутри приложения (для deep links и переходов). Возвращает `true`, если цель поддержана |
| `openDtfLink(e, href)` | обработчик клика по ссылке на dtf.ru: открывает поддерживаемые адреса оверлеями, остальное оставляет браузеру |
| `getPostPath(post)`, `getProfilePath(id)`, `getTagPath(tag)`, `getSearchPath(query)`, `getSettingsPath(page?)` | адреса для `href` |
| `pushSubstate(key, value)`, `popSubstate()` | управление промежуточными внутренними состояниями окон (навигация по подменю без смены URL) |

Ссылки на посты и профили остаются обычными `<a href>`: `openPost`/`openProfile` перехватывают только обычный клик, а клик с Ctrl, Cmd, Shift и средней кнопкой браузер откроет в новой вкладке. Так же работают открытие по прямой ссылке и «копировать адрес».

Профиль может быть указан числовым ID или коротким именем из адреса DTF. Короткое имя сохраняется во внутреннем адресе профиля и разрешается через фасад API при загрузке экрана; запросы записей и подписок используют полученный числовой ID. Поэтому перехват клика остаётся синхронным, а прямая ссылка и новая вкладка работают одинаково. Служебные страницы DTF за имена профилей не принимаются; неизвестное имя показывает обычную ошибку загрузки с повторной попыткой.

При обычном клике обработчики фиксируют происхождение клика (`markOrigin`): координаты и связанный элемент. Если клик произошел по карточке (`data-morph-root`) или аватару (`data-morph="avatar"`), ядро использует связанный переход (раскрытие прямоугольника карточки или перелёт аватара в профиль).

```svelte
<a href={resolve(getPostPath(post) as '/')} onclick={(e) => openPost(e, post)}>{post.title}</a>
```

`openOverlay` построен на `goto(url, { shallow: true, state })` из SvelteKit 3 (в нём вместо устаревших `pushState`/`replaceState` теперь одна функция). Адрес в `resolve()` оборачивается автоматически, так что `BASE_PATH` учитывается.

`openFeed` ведёт себя по-разному в зависимости от места:

- над лентой открыты оверлеи → закрыть все и вернуться к ленте (с той же лентой в адресе);
- уже на ленте → прокрутить вверх и обновить;
- на странице, открытой прямой ссылкой (`/post/1`), ленты под страницей нет → обычный переход на `/`.

## Прямые ссылки

Для каждого оверлея есть и настоящий маршрут, чтобы адрес можно было открыть напрямую или обновить страницу:

| Адрес | Что показывает |
| --- | --- |
| `/post/[id]?source=…` | пост (`PostContent`) |
| `/u/[id]` | профиль по числовому ID или короткому имени (`ProfileContent`) |
| `/settings` | сначала главная, затем открывается окно настроек |
| `/notifications` | список уведомлений (компонент темы `Notifications`) |
| `/tag/[name]` | записи с тегом (`TagContent`) |
| `/search?q=…` | результаты поиска (`SearchContent`); новый поиск из открытого заменяет его, а не копится в истории |
| `/drafts` | черновики вошедшего пользователя (`DraftsContent`) |
| `/login` | вход |
| `/write` | сначала главная, затем открывается редактор |

Обновление страницы с оверлеем (`state` не сохраняется) открывает этот маршрут заново: страницы (`page`) — полноэкранным маршрутом без ленты под ним, окна (`modal`) — лентой с окном поверх.

## Лента в адресе

Выбранная лента лежит в параметре `feed`: `/` (популярное), `/?feed=new` (свежее), `/?feed=my` (подписки). Код: `src/lib/feed.svelte.ts`.

| Что | Как |
| --- | --- |
| Переключить ленту | `openFeedTab('new')`: обычный `goto`, один новый элемент истории. Лента меняется сразу, адрес догоняет |
| Какая лента открыта | страница ленты читает `feedFromUrl()` и сообщает `feed.setCurrent(...)`; боковая панель и страница читают `feed.current` |
| Обновить ленту | `feed.refresh()` (вызывается при клике по логотипу на ленте), обновляется только открытая лента |

Пока поверх ленты открыт оверлей, в адресе его путь, поэтому `feedFromUrl()` возвращает ту ленту, что была раньше. Это нужно, чтобы боковая панель не сбрасывала подсветку, а страница ленты не перезагружалась, когда вы открыли пост.

### Несколько лент сразу

Главная держит открытые ленты все сразу (`feed.kept`): у каждой свой компонент `FeedList` со своими постами, подгруженными страницами и номером запроса. Неактивная лента скрыта через `content-visibility: hidden`: она не рисуется и не занимает места, но браузер хранит её раскладку. Почему так, а не перерисовка из кэша — в [решении 0009](../../decisions/0009-kept-feeds-and-swipe.md).

- **Прокрутка** запоминается для каждой ленты отдельно (`feed.rememberScroll`), пока лента на экране. Другая лента открывается там, где её оставили; та же лента (повторный выбор из-под поста, другой период «Популярного») — сверху.
- **Из-под оверлея.** Лента, выбранная из-под поста, меняется скрыто, а прокрутку для неё (`feed.consumeScrollTarget()`) ставит корневой слой, когда оверлеи закроются.
- **«Назад» между лентами.** Прокрутку ставит страница ленты, поэтому встроенное восстановление SvelteKit для такого шага отключается (`disableScrollHandling`).
- **Период** есть только у «Популярного» и остаётся за ним, пока смотрят другие ленты. `openFeedTab('popular')` без периода открывает выбранный раньше.
- **Свежие посты.** При возврате на ленту, которая стоит у верха, первая страница сверяется с сервером и подменяется, если изменилась.

### Свайп

Жесты пальцем (свайп лент, свайп «назад», свайп по комментарию и обновление жестом) есть только в темах, которые включили их флагом `gestures` в манифесте; флаг не наследуется. В остальных темах касания работают как без жестов: ни обработчиков, ни `touch-action`. Ведение пальца у всех жестов общее (`src/lib/swipe.ts`): только касание, только первый палец, края экрана оставлены системе, ось выбирает браузер, клик после перетаскивания гасится, а доезд начинается со скорости пальца. Новое касание посреди доезда подхватывает его с места, если жест это умеет, иначе мгновенно завершает.

В мобильной раскладке (граница та же, что у настроек «для смартфонов») ленты листаются горизонтальным свайпом в порядке вкладок (`FEEDS`). На широком экране свайпа нет: там вкладки лент видны в боковой колонке. Ограничение по ширине снимается одним флагом в начале модуля. Код: `src/lib/feedSwipe.ts`.

- Палец двигает дорожку с лентами, соседняя лента стоит рядом сразу на своей прокрутке. После отпускания дорожка доезжает до соседней или возвращается: решает бросок, а без него — пройденная доля ширины. У крайней ленты дорожка упирается.
- Доезд — пружина без колебаний, которая по кадрам ведёт тот же сдвиг, что и палец. Касание посреди доезда останавливает дорожку там, где она есть: палец ведёт её дальше в любую сторону и может бросить снова, а отпускание без движения (или вертикальная прокрутка) продолжает доезд с этого места, как после медленного жеста.
- Ось выбирает браузер (`touch-action: pan-y` у дорожки): вертикальный жест остаётся прокруткой, горизонтальный достаётся свайпу. Касание у края экрана не перехватывается: там системный жест «назад».
- Свайп доступен, только когда над лентой нет оверлеев. Доехавший свайп открывает ленту через тот же `openFeedTab`, без анимации появления (её роль играет сам жест).
- Там, где свайп работает (сенсорный экран в мобильной раскладке), соседние ленты строятся заранее, в простое после загрузки открытой: свайп сразу показывает посты.
- Неактивная лента стоит абсолютной и скрытой уже в покое, жест только сдвигает её и делает видимой: позиционирование в первом кадре жеста не меняется.

### Свайп боковой панели

Слева от первой ленты соседа нет: там свайп вправо выдвигает боковую панель, если тема её предоставила (`provideDrawer` из `src/lib/drawerSwipe.ts`). Свайп влево по открытой панели или по странице рядом с ней закрывает её. Работает в тех же условиях, что свайп лент.

- Общий модуль ведёт только положение панели от 0 до 1 и решает, куда доехать (как у свайпа лент: бросок или пройденная доля). Как панель выглядит и что двигается, решает тема.
- Жест подхватывает панель с текущего положения, даже посреди доезда.
- Кнопка меню должна давать тот же вид и тот же доезд, что и свайп: у одной панели не бывает двух анимаций.

### Обновление жестом

От самого верха ленты палец тянет страницу вниз, и отпускание за порогом обновляет открытую ленту. Работает в тех же условиях, что свайп лент, и только если тема рисует этот жест (`providePuller` из `src/lib/pullRefresh.ts`). Код: `src/lib/pullRefresh.ts`, подключён на странице ленты.

- Общий модуль ведёт только сдвиг страницы (с сопротивлением) и решает, пройден ли порог: на пороге срабатывает тактильная отдача. Как выглядят подсказка, щель и загрузка, решает тема.
- Вертикальный жест браузер забирает в прокрутку, поэтому модуль слушает touch-события и отменяет их движение, пока прокрутка не началась. Вверх и вбок жест не забирает: там прокрутка и свайп лент.
- Отпускание за порогом оставляет тему в состоянии загрузки, пока лента не обновится (`feed.refresh(true)` возвращает промис), но не короче небольшого минимума, чтобы загрузка не мелькала. Своего индикатора обновления лента при этом не показывает.
- Пока тема занята (открыта боковая панель, доезжает прошлое обновление), жест не начинается.

### Свайп «назад»

В мобильной раскладке страницу-оверлей (пост, профиль, уведомления) можно закрыть свайпом вправо по её содержимому. Код: `src/lib/swipeBack.svelte.ts`, подключён в корневом layout.

- Палец тянет верхнюю страницу, под ней сразу виден слой, на который вернёмся (страница под ней или лента), с лёгким параллаксом и затемнением. Слой стоит на той прокрутке, на которую встанет окно после закрытия, поэтому после закрытия ничего не прыгает.
- После отпускания страница уезжает и оверлей закрывается через `closeOverlay`, или возвращается на место. Решает бросок, а без него — пройденная доля ширины, как у свайпа лент.
- Жест возможен, только когда верхний оверлей — страница, под ним страница или ничего (под модалкой нельзя), и не идёт универсальный переход. С полей ввода жест не начинается, горизонтальные прокрутки внутри страницы браузер оставляет себе.
- Закрытие жестом само служит анимацией: уход страницы и появление слоя под ней не проигрываются. Слой под страницей встаёт в поток в тот момент, когда layout меняет слои, до того как окно прокручивается на его позицию. Если смена слоёв не пришла, жест через короткое время сбрасывается.

### Свайп по комментарию

Свайп влево по комментарию отвечает на него, как в Telegram. Это не навигация, но жест того же семейства: работает на любой ширине, если касание сенсорное. Код лежит у темы, которая его рисует (компонент комментариев и модуль жеста рядом с ним).

- Комментарий едет за пальцем, справа выезжает значок ответа. После порога сдвиг идёт туго, срабатывает тактильная отдача, и отпускание выполняет действие; до порога комментарий просто возвращается.
- Пока порог пройден, палец вниз выбирает другое действие из колонки (как в Telegram X): ответ стоит там, где сработал порог, под ним — оценка «за» и «против», а при оценках-реакциях — до трёх любимых реакций из настроек «Реакции» (пока их нет — реакции лайка и дизлайка). До порога колонка идёт за пальцем по вертикали. Шаг по вертикали крупнее значков и с запасом у границы, чтобы дрожь пальца не переключала действие. Каждая смена действия — тоже отдача.
- Вправо жест не забирает: на странице-оверлее это свайп «назад». Не начинается с полей ввода, с редактора ответа и с комментариев без кнопки «Ответить» (удалённые, скрытые фильтром).

Раньше лента и обновление переключались событиями `window` (`switchFeed`, `refreshFeed`). Теперь только URL и состояние: событий нет.

## Что менять нельзя

- Не вызывать `pushState`, `replaceState`, `history.pushState` и `history.back()` из компонентов: только `openOverlay` и `closeOverlay`.
- Не использовать `$app/stores`: в SvelteKit 3 он удалён. Состояние страницы: `page` из `$app/state`.
- Не слать для навигации события через `window`.
