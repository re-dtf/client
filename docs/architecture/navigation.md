# Навигация

Посты, профили, настройки, вход и редактор открываются **оверлеями** поверх ленты. Адрес при этом меняется (`/post/123`), кнопка «Назад» работает, а лента остаётся под оверлеем со своей прокруткой и подгруженными постами. Всю работу с оверлеями делает один модуль: `src/lib/navigation.ts`.

## Оверлей

Оверлей — запись в `page.state.overlays` (типы в `src/app.d.ts`):

```ts
type OverlayData =
	| { type: 'post'; data: { postId: number; sourceId: string } }
	| { type: 'profile'; data: { profileId: number } }
	| { type: 'settings' }
	| { type: 'notifications' }
	| { type: 'login' }
	| { type: 'editor'; data?: { postId?: number | null } }
	| { type: 'lightbox'; data: { images: { uuid: string; width: number; height: number }[]; index: number } };

type OverlayState = OverlayData & { id: string; presentation: 'page' | 'modal' | 'fullscreen' };
```

Способ показа (`presentation`) определяется типом:

- **`page`** (пост, профиль, уведомления) — занимает место страницы. Лента под ним скрыта (`display: none`), но не размонтируется. Если открыто несколько, видим только верхний.
- **`modal`** (настройки, вход, редактор) — окно поверх всего с подложкой, рисует `ModalShell`: подложка сразу, окно после загрузки его картинок, спиннер через 800 мс (см. [motion.md](motion.md)). Клик по подложке закрывает его.

- **`fullscreen`** (просмотр картинок) — оверлей сам рисует себя на весь экран, подложки у него нет.

Корневой `+layout.svelte` рисует стек: для каждого оверлея выбирает компонент по `type` (сниппет `overlayContent`), оборачивает по способу показа и запоминает прокрутку нижнего слоя.

## Функции `$lib/navigation`

| Функция | Что делает |
| --- | --- |
| `openOverlay(overlay)` | открыть оверлей: `openOverlay({ type: 'settings' })`. Адрес вычисляется по типу |
| `closeOverlay()` | закрыть верхний (шаг назад по истории, как кнопка «Назад») |
| `openLightbox(images, index, origin?)` | просмотр картинок (PhotoSwipe, грузится при первом открытии). Адрес не меняется, но это шаг истории: «Назад» закрывает просмотр. `origin` — миниатюра, из которой разворачивается кадр |
| `openPost(e, post)` | обработчик клика по ссылке на пост |
| `openProfile(e, id)` | то же для профиля |
| `openFeed(e)` | обработчик клика по логотипу и «Главной» |
| `getPostPath(post)`, `getProfilePath(id)` | адрес для `href` |

Ссылки на посты и профили остаются обычными `<a href>`: `openPost`/`openProfile` перехватывают только обычный клик, а клик с Ctrl, Cmd, Shift и средней кнопкой браузер откроет в новой вкладке. Так же работают открытие по прямой ссылке и «копировать адрес».

При обычном клике обработчики фиксируют происхождение клика (`markOrigin`): координаты и связанный элемент. Если клик произошел по карточке (`data-morph-root`) или аватару (`data-morph="avatar"`), ядро использует связанный переход (раскрытие прямоугольника карточки или перелёт аватара в профиль).

```svelte
<a href={resolve(getPostPath(post) as '/')} onclick={(e) => openPost(e, post)}>{post.title}</a>
```

`openOverlay` построен на `goto(url, { shallow: true, state })` из SvelteKit 3 (в нём вместо устаревших `pushState`/`replaceState` теперь одна функция). Адрес в `resolve()` оборачивается автоматически, так что `BASE_PATH` учитывается.

`openFeed` ведёт себя по-разному в зависимости от места:

- над лентой открыты оверлеи → закрыть все и вернуться к ленте (с той же лентой в адресе);
- уже на ленте → прокрутить вверх и обновить;
- на странице, открытой прямой ссылкой (`/post/1`), ленты под страницей нет → обычный переход на `/`.

## Прямые ссылки

Для каждого оверлея есть и настоящий маршрут, чтобы адрес можно было открыть напрямую или обновить страницу:

| Адрес | Что показывает |
| --- | --- |
| `/post/[id]?source=…` | пост (`PostContent`) |
| `/u/[id]` | профиль (`ProfileContent`) |
| `/settings` | сначала главная, затем открывается окно настроек |
| `/notifications` | список уведомлений (`NotificationsContent`) |
| `/login` | вход |
| `/write` | сначала главная, затем открывается редактор |

Обновление страницы с оверлеем (`state` не сохраняется) открывает этот маршрут заново: страницы (`page`) — полноэкранным маршрутом без ленты под ним, окна (`modal`) — лентой с окном поверх.

## Лента в адресе

Выбранная лента лежит в параметре `feed`: `/` (популярное), `/?feed=new` (свежее), `/?feed=my` (подписки). Код: `src/lib/feed.svelte.ts`.

| Что | Как |
| --- | --- |
| Переключить ленту | `openFeedTab('new')`: обычный `goto`, один новый элемент истории |
| Какая лента открыта | страница ленты читает `feedFromUrl()` и сообщает `feed.setCurrent(...)`; боковая панель читает `feed.current` |
| Обновить ленту | `feed.refresh()` (вызывается при клике по логотипу на ленте), страница реагирует на `feed.refreshCount` |

Пока поверх ленты открыт оверлей, в адресе его путь, поэтому `feedFromUrl()` возвращает ту ленту, что была раньше. Это нужно, чтобы боковая панель не сбрасывала подсветку, а страница ленты не перезагружалась, когда вы открыли пост.

Страница ленты запоминает номер запроса: ответ прежней ленты не перетирает новую, если вы переключились быстро.

Раньше лента и обновление переключались событиями `window` (`switchFeed`, `refreshFeed`). Теперь только URL и состояние: событий нет.

## Что менять нельзя

- Не вызывать `pushState`, `replaceState`, `history.pushState` и `history.back()` из компонентов: только `openOverlay` и `closeOverlay`.
- Не использовать `$app/stores`: в SvelteKit 3 он удалён. Состояние страницы: `page` из `$app/state`.
- Не слать для навигации события через `window`.
