# Настройки

Экран настроек общий для всех тем. Это окно в духе Adwaita: слева боковая панель с двухуровневой иерархией (основные категории с краткими описаниями, которые либо открывают страницу сразу, либо раскрывают подменю категории со стрелкой назад; размеры и цвета взяты из `navigation-sidebar` libadwaita), справа страница выбранного раздела из карточек (или заглушка с подсказкой, если раздел или подпункт ещё не выбран). На узком окне это последовательный drill-down: список разделов, затем страница с кнопкой «Назад». Также поддерживается режим Solo (сфокусированное открытие раздела без бокового сайдбара с кнопкой возврата). Ширину определяет само окно (container query), а не экран. На телефоне окно занимает весь экран. Окно всегда открывается оверлеем поверх ленты, адрес `/settings` по прямой ссылке сначала открывает ленту, затем окно. Внутри окна прокручивается только страница или список разделов, фон под ним не двигается.

Страницы делятся на два вида:

- **Общие** — то, что не зависит от темы: аккаунт и профиль DTF, уведомления, единый чёрный список (локальные фильтры по тегам и словам + серверный список DTF), источники данных и прокси для входа, выбор темы, настройки ленты и комментариев, реакции, статистика, разделы «Хочу помочь», «Поддержавшие проект» и «О приложении».
- **Настройки темы** — параметры оформления, распределённые по логическим группам («Общее», «Оценки», «Редактор») из схемы активной темы (`themeSettingsSchema`). Если у темы настроек нет, показываются только общие параметры.

Открыть окно сразу на нужной странице можно через данные оверлея: `openOverlay({ type: 'settings', data: { page: 'account', solo: true } })`.

Цвета окна лежат в CSS-переменных `--st-*` на его корне; тема переопределяет их значениями `--theme-st-*`. Акцент, шрифт и цвет текста берутся у активной темы (`--color-blue`, `--font-family`, `--text-primary`). Примитивы читают эти переменные и работают только внутри окна. Оформление отделено от данных: смена вёрстки не затрагивает схему и сохранение.

## Общие настройки

Хранятся одним объектом `redtf:settings`:

```ts
interface AppSettings {
	theme: string;                  // id темы
	proxies: ProxyItem[];           // список CORS-прокси для входа и обновления с failover
	commentNesting: 'flatten' | 'autopan';
	commentVirtualization: 'auto' | 'enabled' | 'disabled';
	recommendations: 'auto' | 'button'; // лента рекомендаций под постом: подгружать сама или по кнопке
	collectStats: boolean;          // вести локальную статистику
	haptics: boolean;               // тактильный отклик
	disableMobileTopBar: boolean;   // отключать верхний бар в мобильной версии
	watermark: boolean;             // невидимая подпись reDTF к отправляемым комментариям
	clientBadges: 'all' | 'redtf_only' | 'none'; // отображение бейджей клиентов комментариев
	mobileBadgesPosition: 'author' | 'date';     // позиция бейджей клиентов
	autoUpvoteComments: boolean;    // голос за себя при публикации комментария (как на Reddit)
	appIcon: AppIconId;             // иконка приложения и вкладки
	customIconData?: string | null; // пользовательская иконка
	debugSafeAreaOverlay?: boolean; // отладка safe-area
	debugHud?: boolean;             // плавающий HUD метрик
	devMode?: boolean;              // режим разработчика
}
```

Управление CORS-прокси вынесено на страницу «Сеть и прокси». Поддерживается последовательный перебор (failover): если первый сервер не отвечает, запрос повторяется через следующий активный прокси. По умолчанию включён открытый прокси на Val Town (с ссылкой на исходный код), доступен резервный на Cloudflare Workers и добавление собственных серверов.

## Реакции и рейтинг

Лайков и дизлайков на DTF нет, есть только реакции, и сервер считает любую из них плюсом. Поэтому «оценка» поста или комментария строится на клиенте по правилам пользователя. Правила общие для всех тем и лежат в `redtf:settings:reactions`:

```ts
interface ReactionSettings {
	rules: Record<number, { kind: 'positive' | 'neutral' | 'negative'; weight: number }>; // только изменённые
	like: number;     // реакция кнопки «лайк»
	dislike: number;  // реакция кнопки «дизлайк»
	rank: boolean;    // сортировать по рейтингу из реакций
}
```

- Каталог реакций (картинка, название, вид и вес по умолчанию) — `config/reactions.ts`. В `rules` попадает только то, что пользователь поменял, поэтому новая реакция в каталоге подхватывается сама. Реакция вне каталога нейтральная.
- `lib/reactions.ts` считает оценку (очки «за» и «против», своя оценка, рейтинг) и сортирует. Темы берут числа оттуда, а не считают сами. У источников без реакций остаётся то, что прислали в `likes`.
- Кнопки «лайк» и «дизлайк» в темах не знают номеров реакций: берут их из хранилища. Если выбранная реакция перестала быть плюсовой (минусовой), берётся первая подходящая.
- Сортировка. Сервер ранжирует по своим очкам, поэтому фасад `api` пересортировывает по рейтингу каждую загруженную порцию: «Популярное» (любой период) и комментарии «Лучшие» (а также «Худшие» — от наименьшего рейтинга к наибольшему). Закреплённое остаётся сверху, при равенстве порядок сервера. Уже показанные элементы не переставляются, см. [решение 0007](../../decisions/0007-client-side-reaction-ranking.md).

## Выбор цветовой палитры

В разделе выбора темы список палитр строится из её манифеста. Системный вариант выбирает палитру по соответствию, заданному темой; изменение системного режима учитывается только при этом выборе.

Выбранный идентификатор хранится в поле `palette` ключа `redtf:theme:<id>`, отдельно от общих настроек. При переключении темы восстанавливается её собственный выбор. Поле зарезервировано ядром, его не следует повторно объявлять в пользовательской схеме настроек темы. Неизвестное значение отображается как палитра по умолчанию без перезаписи сохранённых данных.

Набор и оформление палитр описаны в [архитектуре тем](themes.md#цветовые-палитры).

## Настройки темы

Тема описывает свои настройки схемой в `theme.ts`. Экран сам рисует поля и сохраняет значения, самой теме писать интерфейс не нужно.

```ts
settings: [
	{
		key: 'votes',
		type: 'radio',
		title: 'Оценки',
		description: 'Как выглядят оценки постов и комментариев.',
		default: 'likes',
		options: [
			{ value: 'rating', title: 'Стрелки · осень 2022', description: '…' },
			{ value: 'likes', title: 'Лайки · начало 2023' }
		]
	}
]
```

Типы полей (`themes/types.ts`):

| `type` | Значение | Как выглядит |
| --- | --- | --- |
| `radio` | `string` из `options` | группа строк с галочкой у выбранной, у каждого варианта заголовок и описание |
| `select` | `string` из `options` | строка с выпадающим списком |
| `toggle` | `boolean` | строка с переключателем |

Поля могут зависеть от других настроек через свойство `dependsOn` (поле показывается только при выбранном значении):

```ts
{
	key: 'arrowsSide',
	type: 'radio',
	title: 'Стрелки оценки',
	dependsOn: { key: 'votes', value: 'rating' },
	options: […]
}
```

Также поле можно ограничить конкретным типом устройства через `device: 'mobile' | 'desktop'` (порог — 719px, на смартфонах `mobile`, на десктопах `desktop`):

```ts
{
	key: 'mobileBarBlur',
	type: 'toggle',
	title: 'Блюр мобильного бара',
	device: 'mobile'
}
```

Значения лежат в `redtf:theme:<id темы>`, **у каждой темы свои**: при смене темы настройки старой не теряются, а новой не смешиваются со старыми. Новые поля в схеме подхватывают значение по умолчанию, а несовместимые изменения формата мигрируются через функцию `migrate` в `persistedState`.

### Как тема читает свои настройки

```ts
// themes/dtf2022/themeSettings.svelte.ts
import { activeThemeSettings } from '../settings.svelte';

export const themeSettings = {
	get votes(): VotesStyle {
		return activeThemeSettings().value.votes as VotesStyle;
	}
};
```

Компоненты читают `themeSettings.votes`. `activeThemeSettings()` отдаёт хранилище **выбранной** темы, поэтому в форке тот же код читает значения форка.

### Форки

Схема форка = схема основы + свои поля (поле с тем же `key` заменяет поле основы). Значения форк хранит у себя.
