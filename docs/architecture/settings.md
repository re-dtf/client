# Настройки

Экран настроек общий для всех тем. Это окно в духе Adwaita: слева боковая панель (плоский список разделов со значками, выбранный подсвечен плашкой; размеры и цвета взяты из `navigation-sidebar` libadwaita), справа страница выбранного раздела из карточек. На узком окне это два шага: список разделов, затем страница с кнопкой «Назад». Ширину определяет само окно (container query), а не экран. На телефоне окно занимает весь экран. Окно всегда открывается оверлеем поверх ленты, адрес `/settings` по прямой ссылке сначала открывает ленту, затем окно. Внутри окна прокручивается только страница или список разделов, фон под ним не двигается.

Страницы делятся на два вида:

- **Общие** — то, что не зависит от темы: источники данных и прокси для входа, выбор темы, режим вложенных комментариев, реакции, статистика, раздел «Хочу помочь».
- **Страница темы** — настройки выбранной темы (например, вид оценок у `dtf2022`). Её название — название темы. Если у темы настроек нет, страницы нет.

Где живёт код:

| Файл | Роль |
| --- | --- |
| `components/settings/SettingsScreen.svelte` | окно: разделы слева, список страниц и выбор, что показать |
| `components/settings/SettingsIcon.svelte` | значки разделов боковой панели (по id страницы); новая страница — новая ветка в нём |
| `components/settings/FieldControl.svelte` | один пункт настроек по описанию поля |
| `components/settings/SettingsGroup.svelte`, `SettingsRow.svelte`, `SettingsSwitch.svelte`, `SettingsSelect.svelte`, `SettingsSegmented.svelte`, `SettingsButton.svelte` | примитивы оформления: группа-карточка, строка, переключатель, выпадающий список, сегментированный выбор, кнопка |
| `components/settings/AccountSettings.svelte`, `DtfSettings.svelte`, `IgnoredSettings.svelte`, `AccountGate.svelte` | страницы «Аккаунт» (имя и описание профиля), «DTF» (ленты и уведомления) и «Чёрный список» (скрытые пользователи и темы, с кнопкой «Убрать»). Открыть окно сразу на нужной странице можно через данные оверлея: `openOverlay({ type: 'settings', data: { page: 'account' } })`.

Цвета окна лежат в CSS-переменных `--st-*` на корне `SettingsScreen`, акцент, шрифт и цвет текста берутся у активной темы (`--color-blue`, `--font-family`, `--text-primary`). Примитивы читают эти переменные и работают только внутри окна. Оформление отделено от данных: смена вёрстки не затрагивает схему и сохранение.

## Общие настройки

Хранятся одним объектом `redtf:settings`:

```ts
interface AppSettings {
	theme: string;                  // id темы
	proxyUrl: string;               // CORS-прокси для входа
	commentNesting: 'flatten' | 'autopan';
	collectStats: boolean;          // вести локальную статистику
	haptics: boolean;               // тактильный отклик
	disableMobileTopBar: boolean;   // отключать верхний бар в мобильной версии
}
```

Читать и писать: `settings.value.proxyUrl`, `settings.patch({ proxyUrl })` (из `$lib/storage/settings.svelte`). Тему переключает `activeTheme.set(id)`, читать её нужно через `activeTheme.id` (если выбранной темы больше нет, вернётся тема по умолчанию).

Прокси по умолчанию (`DEFAULT_PROXY_URL`) приходит из `VITE_AUTH_PROXY_URL` при сборке. Если переменная пуста, кнопки «Использовать прокси от автора» нет.

## Реакции и рейтинг

Лайков и дизлайков на DTF нет, есть только реакции, и сервер считает любую из них плюсом. Поэтому «оценка» поста или комментария строится на клиенте по правилам пользователя. Правила общие для всех тем и лежат в `redtf:settings:reactions`:

```ts
interface ReactionSettings {
	rules: Record<number, { kind: 'positive' | 'neutral' | 'negative'; weight: number }>; // только изменённые
	like: number;     // реакция кнопки «лайк»
	dislike: number;  // реакция кнопки «дизлайк»
	rank: boolean;    // сортировать по рейтингу из реакций
}
```

- Каталог реакций (картинка, название, вид и вес по умолчанию) — `config/reactions.ts`. В `rules` попадает только то, что пользователь поменял, поэтому новая реакция в каталоге подхватывается сама. Реакция вне каталога нейтральная.
- `lib/reactions.ts` считает оценку (очки «за» и «против», своя оценка, рейтинг) и сортирует. Темы берут числа оттуда, а не считают сами. У источников без реакций остаётся то, что прислали в `likes`.
- Кнопки «лайк» и «дизлайк» в темах не знают номеров реакций: берут их из хранилища. Если выбранная реакция перестала быть плюсовой (минусовой), берётся первая подходящая.
- Сортировка. Сервер ранжирует по своим очкам, поэтому фасад `api` пересортировывает по рейтингу каждую загруженную порцию: «Популярное» (любой период) и комментарии «Лучшие». Закреплённое остаётся сверху, при равенстве порядок сервера. Уже показанные элементы не переставляются, см. [решение 0007](../../decisions/0007-client-side-reaction-ranking.md).

## Настройки темы

Тема описывает свои настройки схемой в `theme.ts`. Экран сам рисует поля и сохраняет значения, самой теме писать интерфейс не нужно.

```ts
settings: [
	{
		key: 'votes',
		type: 'radio',
		title: 'Оценки',
		description: 'Как выглядят оценки постов и комментариев.',
		default: 'likes',
		options: [
			{ value: 'rating', title: 'Стрелки · осень 2022', description: '…' },
			{ value: 'likes', title: 'Лайки · начало 2023' }
		]
	}
]
```

Типы полей (`themes/types.ts`):

| `type` | Значение | Как выглядит |
| --- | --- | --- |
| `radio` | `string` из `options` | группа строк с галочкой у выбранной, у каждого варианта заголовок и описание |
| `select` | `string` из `options` | строка с выпадающим списком |
| `toggle` | `boolean` | строка с переключателем |

Значения лежат в `redtf:theme:<id темы>`, **у каждой темы свои**: при смене темы настройки старой не теряются, а новой не смешиваются со старыми. Поля, добавленные в схему позже, получают значение по умолчанию без миграций.

### Как тема читает свои настройки

```ts
// themes/dtf2022/themeSettings.svelte.ts
import { activeThemeSettings } from '../settings.svelte';

export const themeSettings = {
	get votes(): VotesStyle {
		return activeThemeSettings().value.votes as VotesStyle;
	}
};
```

Компоненты читают `themeSettings.votes`. `activeThemeSettings()` отдаёт хранилище **выбранной** темы, поэтому в форке тот же код читает значения форка.

### Форки

Схема форка = схема основы + свои поля (поле с тем же `key` заменяет поле основы). Значения форк хранит у себя.
