# Хранилище

Всё, что приложение запоминает, лежит в `localStorage` и проходит через одну функцию `persistedState` (`src/lib/storage/persisted.svelte.ts`). Другого пути нет: прямой `localStorage.getItem` в коде запрещён.

## Слои и ключи

Ключ имеет вид `redtf:<слой>:<имя>`. Слой показывает, что это за данные и как с ними поступать (экспортировать, сбрасывать, не показывать).

| Слой | Что хранит | Можно экспортировать | Можно сбросить без потерь |
| --- | --- | --- | --- |
| `settings` | выбор пользователя, не зависящий от темы | да | нет |
| `theme` | настройки конкретной темы, по ключу на тему | да | нет |
| `secrets` | токены и сессии | **нет** | нет (придётся войти заново) |
| `data` | данные, которые пользователь накопил: подключённые источники и их разрешения | да | нет |
| `cache` | копии данных API ради скорости | нет | да |

Экспорта и сброса настроек в приложении пока нет: колонки показывают, как слои будут вести себя, когда они появятся. Слой уже сейчас определяет, куда класть данные.

Все ключи сейчас:

| Ключ | Слой | Содержимое | Файл |
| --- | --- | --- | --- |
| `redtf:settings` | settings | `{ theme, proxyUrl, commentNesting }` | `storage/settings.svelte.ts` |
| `redtf:theme:<id>` | theme | значения полей настроек темы | `themes/settings.svelte.ts` |
| `redtf:secrets:dtf-session` | secrets | сессия DTF: токены и сроки | `storage/auth.svelte.ts` |
| `redtf:secrets:source-tokens` | secrets | токены подключённых источников по их id | `storage/sources.svelte.ts` |
| `redtf:data:sources` | data | подключённые источники: манифесты, разрешения, включён ли | `storage/sources.svelte.ts` |
| `redtf:data:bio-cleanup` | data | отложенная очистка «О себе» после проверки владения аккаунтом | `storage/sources.svelte.ts` |
| `redtf:cache:current-user` | cache | вошедший пользователь, чтобы аватар в шапке был сразу | `api/currentUser.svelte.ts` |

Зарезервировано: `redtf:setup:*` — для мастера первой настройки. Ключ `redtf:setup:completed` читают `app.html` (какую заставку показать) и корневой layout напрямую как строку; когда мастер появится, его стоит перевести на `persistedState`.

## Как пользоваться

```ts
import { persistedState } from '$lib/storage/persisted.svelte';

const store = persistedState('redtf:settings', { theme: 'dtf2022', proxyUrl: '' });

store.value;                         // прочитать, реактивно
store.value = { theme: 'x', proxyUrl: '' };   // заменить целиком
store.patch({ proxyUrl: 'https://…' });       // заменить часть полей объекта
```

Значение **заменяется целиком**, а не мутируется (`store.value.theme = 'x'` не сохранится). Внутри используется `$state.raw`, поэтому глубокая реактивность не нужна и лишних прокси нет.

Для `bind:` используйте функциональную привязку:

```svelte
<input bind:value={() => settings.value.proxyUrl, (v) => settings.patch({ proxyUrl: v })} />
```

Модули вроде `storage/auth.svelte.ts` оборачивают `persistedState` в объект с понятным API (`authStorage.session`, `sourceStorage.getToken(id)`), чтобы остальной код не знал про ключи.

## Что делает `persistedState`

- Хранит данные в виде `{ v: версия, d: данные }`.
- **Версия.** Если версия в хранилище не совпала с той, что указана в коде (`persistedState(key, defaults, version)`), данные отбрасываются и берётся значение по умолчанию. Это единственный механизм совместимости. **Миграций нет** (см. [ADR 0002](../decisions/0002-storage-layers-without-migrations.md)).
- **Дополнение по умолчанию.** Если значение — объект, поля из `defaults`, которых нет в сохранённых данных, добавляются. Так новую настройку можно ввести без повышения версии.
- **Другие вкладки.** Изменение в соседней вкладке приходит через событие `storage` и обновляет значение.
- **Устойчивость.** Битый JSON, переполнение квоты и недоступный localStorage (приватный режим) не роняют приложение: пишется ошибка в консоль, значение остаётся по умолчанию.
- **Запись сразу.** Присваивание пишет в `localStorage` синхронно, без эффектов.

## Токены

Токены лежат в слое `secrets`, отдельно от манифестов и настроек. Это значит, что будущий экспорт настроек и данных не сможет случайно захватить токен, а удаление источника убирает и его токен. Просроченные токены источников удаляются при запуске, а `getToken` не меняет состояние.

Токены хранятся в открытом виде: у статичного SPA нет места для ключа шифрования, которому можно было бы доверять. Не добавляйте в localStorage ничего, чего вы не готовы увидеть в DevTools пользователя.

## Добавить новый ключ

1. Выберите слой по таблице выше. Если не подходит ни один, остановитесь и обсудите: слои — часть архитектуры.
2. Заведите `persistedState('redtf:<слой>:<имя>', defaults)` в модуле рядом с тем, кто использует данные.
3. Допишите ключ в таблицу выше.
4. Если меняете формат существующего ключа несовместимо, увеличьте `version`.
