# Темы

Тема — это папка в `src/lib/themes/<id>/` с набором Svelte-компонентов, стилями и описанием (манифестом). Приложение показывает компоненты активной темы, а общая логика (данные, навигация, настройки) у всех тем одна.

## Состав темы

```
themes/base-theme/
  theme.ts            манифест: id, название, extends, схема настроек
  theme.css           глобальные стили темы: токены, шрифт (только для [data-theme~="base-theme"])
  Header.svelte       компоненты, которые рисует ThemeLoader (только корень папки)
  Post.svelte
  …
  post/, comments/    внутренности темы: подкомпоненты, утилиты, ассеты
```

**Правило корня.** `ThemeLoader` видит только файлы `*.svelte` прямо в папке темы. Всё, что лежит глубже, — внутренность темы, снаружи (и из форков) оно недоступно как «компонент темы».

## Манифест `theme.ts`

```ts
import { defineTheme } from '../types';

export default defineTheme({
	id: 'base-theme',                 // совпадает с именем папки
	name: 'Базовая тема',              // название в настройках
	description: '…',
	extends: undefined,            // id темы-основы, если это форк
	motion: undefined,             // анимации темы (например fluent из $lib/motion), см. motion.md; не наследуется
	gestures: undefined,           // true — жесты пальцем (свайп лент, «назад», по комментарию), см. navigation.md; не наследуется
	settings: [/* поля настроек, см. settings.md */]
});
```

Реестр (`themes/registry.ts`) находит все `*/theme.ts` сам (`import.meta.glob`), отдельно регистрировать тему не нужно.

## Цветовые палитры

Тема определяет доступные палитры полем `palettes` в манифесте. Идентификаторы произвольные; `auto` зарезервирован для системного выбора.

```ts
palettes: {
	default: 'paper',
	system: { light: 'paper', dark: 'night' },
	options: [
		{ id: 'paper', title: 'Бумага', mode: 'light', background: '#f2f2f2', themeColor: '#ddeeff' },
		{ id: 'night', title: 'Ночь', mode: 'dark', background: '#111111', themeColor: '#222222' }
	]
}
```

- `options` содержит хотя бы одну палитру с уникальным идентификатором.
- `default` и обе ссылки в `system` указывают на палитры этого набора. Тема с одной палитрой связывает оба системных режима с ней.
- `mode` определяет оформление нативных элементов, общих компонентов и статус-бара. Разные палитры могут иметь одинаковый базовый режим.
- `background` задаёт фон страницы до загрузки CSS темы, `themeColor` — цвет панели браузера.
- Новая установка выбирает системный вариант. Неизвестное сохранённое значение заменяется палитрой `default` при чтении, без записи в хранилище.

На `<html>` выставляются конкретная палитра (`data-palette`) и вычисленный базовый режим (`data-theme-mode`). В CSS темы не нужно заново проверять системный режим:

```css
:root[data-theme~="my-theme"][data-theme-mode="dark"] {
	--text-primary: #eeeeee;
}

:root[data-theme~="my-theme"][data-palette="night"] {
	--bg-main: #111111;
	--bg-card: #222222;
}
```

CSS каждой палитры также ограничивается идентификатором темы: палитры разных тем могут называться одинаково. Цвета окна настроек тема переопределяет через переменные `--theme-st-*`, например `--theme-st-bg` и `--theme-st-card`; внутри окна используются `--st-*` со значениями по умолчанию.

Форк без собственного `palettes` наследует весь набор основы. Собственный набор заменяет унаследованный целиком: список, палитру по умолчанию и системные соответствия. Выбор пользователя хранится отдельно для каждого форка.

Ранний запуск и приложение используют одни манифесты и правила разрешения палитры. Сборка встраивает синхронный скрипт оформления в HTML до загрузки Svelte; вручную дублировать темы и палитры в шаблоне не нужно. Манифесты должны оставаться пригодными для раннего запуска, без зависимости от состояния приложения.

## Контракт компонентов

`themes/contract.ts` — единственное место, где написано, какие компоненты есть у темы и какие пропсы им передаются:

| Компонент | Обязателен | Что рисует |
| --- | --- | --- |
| `Header` | да | шапка |
| `MainLayout` | нет | каркас страницы (колонки, панели); без него содержимое выводится как есть |
| `EditorialNews` | да | блок новостей редакции над лентой |
| `FeedTabs` | да | переключатель лент и период «Популярного» (`period`, `switchPeriod`) |
| `Post` | да | пост: карточка в ленте (`preview`) и полная страница |
| `Comments` | да | комментарии поста |
| `Profile` | да | страница профиля |
| `Notifications` | да | страница уведомлений |
| `TagPage` | да | записи с тегом; данные грузит ядро (`TagContent`), тема рисует заголовок и список |
| `SearchPage` | да | результаты поиска: вкладки, порядок, записи и блоги; данные и подгрузку ведёт ядро (`SearchContent`) |
| `DraftsPage` | да | черновики; клик открывает редактор (`onopen`) |
| `LoginModal` | да | окно входа (форма почты и токена, выбор прокси); открывается и как оверлей, и на странице `/login` |
| `NetworkErrorModal` | да | модальное окно сетевой ошибки с кнопками повтора и закрытия (`error`, `onretry`, `onclose`) |
| `FeedNotice` | нет | плашка между постами ленты с просьбой поддержать проект (`onlater`, `onnever`); без неё в ленте ничего не показывается, когда показывать — решает ядро (`feedNotice.svelte.ts`) |
| `Recommendations` | нет | лента рекомендаций под комментариями поста (`postId`, только записи DTF); данные тема грузит сама через `api.getRecommendations`; без неё под постом ничего не показывается |
| `EditorScreen` | да | экран редактора |
| `Spinner` | да | индикатор загрузки (`inline` — маленький; `block` — заглушка на месте содержимого, если тема умеет) |
| `ReloadPrompt` | да | предложение обновить приложение |

`ThemeLoader` типизирован по контракту: `<ThemeLoader componentName="Post" {post} />` проверяется компилятором. Компонент темы объявляет пропсы так же, как в контракте.

Нет обязательного компонента в теме и её основах — `ThemeLoader` покажет красную рамку с ошибкой (в разработке это сразу видно). Запасных вариантов в ядре нет: разметку страниц и окон рисует только тема. Необязательный компонент (`MainLayout`, `FeedNotice`, `Recommendations`) ядро показывает, только если он есть у темы (`hasThemeComponent`); без `MainLayout` содержимое выводится как есть.

## Как `ThemeLoader` находит компонент

1. Берёт цепочку активной темы: `['my-fork', 'base-theme']` (сама тема, затем основа, затем её основа).
2. Идёт по цепочке и берёт первый найденный `<тема>/<Имя>.svelte`.
3. Первый раз загружает его динамическим `import()` и запоминает; если ожидание затянулось дольше полусекунды, показывает `Spinner`. Все следующие `ThemeLoader` с тем же компонентом рисуют его сразу.

Промис загрузки один на путь: если Svelte пересчитает блок `{#await}`, он получит тот же промис и не пересоздаст компонент.

## Стили

- **Глобально у темы только `theme.css`**: CSS-переменные (токены), шрифт, базовые правила. Остальное — стили внутри компонентов (`<style>` Svelte).
- Стили темы подключаются лениво при её выборе и **не выгружаются**, поэтому все правила `theme.css` ограничены селектором `[data-theme~="<id>"]`. Тогда стили невыбранной темы ничего не делают.
- Атрибут `data-theme` на `<html>` содержит всю цепочку через пробел: `data-theme="my-fork base-theme"`. Оператор `~=` проверяет «содержит слово», поэтому правила основы работают и в форке.
- Стили грузятся от основы к форку, так что форк переопределяет основу обычным каскадом.
- Атрибут ставится только **после** загрузки стилей, чтобы не было вспышки неоформленной страницы.
- Общие компоненты (`components/`) оформляются через CSS-переменные с запасными значениями (`var(--text-muted, #707070)`), а тема подставляет свои токены.

## Форки темы

Форк — тема с `extends`. Он берёт у основы всё, чего у себя не переопределил: компоненты, стили, настройки. Исправления основы попадают в форк автоматически. Подробный пример: [guides/add-a-theme.md](../guides/add-a-theme.md).

Что наследуется:

- **Компоненты корня**: положили `Post.svelte` в форк — используется он, иначе берётся из основы.
- **Стили**: `theme.css` основы подключается первым, потом форка.
- **Палитры**: набор основы, если форк не объявил свой.
- **Схема настроек**: поля основы плюс свои; поле с тем же `key` заменяет поле основы.

Что не наследуется:

- **Значения настроек.** У форка свой ключ `redtf:theme:<id форка>`: у каждой темы настройки отдельные, при переключении они сохраняются.
- **Подкомпоненты основы** можно импортировать как обычный код (`import PostCard from '../base-theme/post/PostCard.svelte'`), но тогда форк привязан к внутренностям основы. Лучше переопределять компонент корня целиком или менять токены.

Почему не git-сабмодули и не копирование: [ADR 0003](../../decisions/0003-theme-inheritance-instead-of-submodules.md).

## Тема из внешнего репозитория

Пока не поддерживается: все темы собираются в бандл на этапе сборки. Если понадобится, тему можно будет подключать как npm-пакет с тем же манифестом и компонентами, а реестр дополнить чтением из пакета.
