# 0001. Статичное SPA без SSR и без своего сервера

Статус: принято
Дата: 2026-11-01

## Контекст

reDTF работает с аккаунтами и токенами DTF. Пользователь должен иметь возможность убедиться, что приложение не пересылает его данные никуда, кроме `api.dtf.ru` и выбранных им источников. Хостинг должен быть бесплатным и простым (GitHub Pages, Cloudflare Pages).

## Решение

Приложение — статические файлы: `adapter-static`, `ssr = false`, все запросы делает браузер. Серверного кода нет (единственный `+server.ts` пререндерится в статический `version.json`).

Для того, что нельзя сделать из браузера (вход и обновление токена: DTF не отдаёт на них CORS-заголовки), используется отдельный минимальный прокси, который пользователь может развернуть сам ([reDTF-proxy](https://github.com/re-dtf/proxy)). Адрес прокси задаётся при сборке (`VITE_AUTH_PROXY_URL`) и в настройках, зашитого адреса в коде нет.

## Последствия

- Проверяемо: сетевую активность видно в DevTools, исходный код прокси — 30 строк.
- Нет SEO и серверного рендера: для клиента это не нужно.
- Всё, что требует секрета на сервере, невозможно. Токены хранятся в `localStorage` в открытом виде (см. [0002](0002-storage-layers-without-migrations.md)).
- Отдельный прокси — единственное звено, которому нужно доверять при входе: через него проходят пароль и токен обновления.
