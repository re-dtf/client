# Добавить тему или форк

Прочитайте сначала [architecture/themes.md](../architecture/themes.md): здесь только порядок действий.

## Форк существующей темы (самый частый случай)

Пример: тема `dtf2022-compact` — та же `dtf2022`, но с другими токенами и своей карточкой поста.

1. Создайте папку `src/lib/themes/dtf2022-compact/`.
2. Добавьте манифест `theme.ts`:

   ```ts
   import { defineTheme } from '../types';

   export default defineTheme({
   	id: 'dtf2022-compact',          // как имя папки
   	name: 'DTF 2022, компактная',
   	description: 'Плотная лента без боковых панелей',
   	extends: 'dtf2022'
   });
   ```

   Тема уже появилась в списке тем в настройках и выбирается. Всё, чего в форке нет, берётся из `dtf2022`.

3. Если нужны свои стили, добавьте `theme.css`. Правила **обязательно** ограничивайте `[data-theme~="dtf2022-compact"]` (знак `~=`, а не `=`), иначе они заденут другие темы:

   ```css
   :root[data-theme~="dtf2022-compact"] {
   	--sidebar-left-width: 0px;
   }
   ```

   Стили основы подключены раньше, поэтому форк переопределяет только то, что указал.

4. Если нужен свой компонент, положите файл с тем же именем в корень папки форка, например `Post.svelte`. Пропсы берите из `themes/contract.ts` (`ThemeComponents['Post']`). Подкомпоненты основы можно импортировать (`../dtf2022/post/PostBlocks.svelte`), но это привязывает форк к её внутренностям.

5. Если нужны свои настройки, добавьте `settings: [...]` в манифест: поля основы сохраняются, а поле с тем же `key` заменяется. Значения у форка свои (`redtf:theme:dtf2022-compact`).

6. Если форку нужны анимации, добавьте `motion: fluent` (`import { fluent } from '$lib/motion'`) или свой объект. Поле не наследуется: без него форк `dtf2022` не анимирует ничего. Подробнее: [architecture/motion.md](../architecture/motion.md).

7. Проверьте в браузере: выберите тему в настройках, пройдите ленту, пост, профиль и настройки на ширине 1280 и 390.

Что нельзя: менять файлы основы ради форка (правка должна быть полезна всем темам-наследникам), копировать компоненты основы целиком «на всякий случай» (они перестанут получать исправления), писать правила `theme.css` без `[data-theme~=…]`.

## Новая тема с нуля

1. Папка `src/lib/themes/<id>/` и `theme.ts` без `extends`.
2. Все обязательные компоненты из `themes/contract.ts` в корне папки: `Header`, `EditorialNews`, `FeedTabs`, `Post`, `Comments`, `EditorScreen`, `Spinner`, `ReloadPrompt`. Необязательные (`MainLayout`, `Profile`, `Notifications`, `LoginModal`) добавляйте по мере нужды, иначе покажется запасной вариант.
3. `theme.css` с токенами и шрифтом, всё под `[data-theme~="<id>"]`.
4. Настройки темы через `settings` в манифесте.
5. Общие компоненты (`components/BlockRenderer`, `Comments/…`, `editor/…`) оформляются CSS-переменными: задайте их в `theme.css`.

Новую тему стоит согласовать заранее: поддерживать её придётся вместе с остальными.

## Проверка

- `npm test`: тесты реестра подхватят манифест.
- `npm run check`: компоненты темы типизируются по контракту.
- Переключение на тему и обратно не оставляет следов в оформлении (стили чужих тем не должны влиять на экран).
