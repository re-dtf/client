# Приватность и безопасность

> Статус: черновик. Перед релизом вычитать вместе с владельцем проекта.

## Куда уходят ваши данные

- Запросы идут **из вашего браузера напрямую** в API DTF (`api.dtf.ru`). У reDTF нет своего сервера, который мог бы их видеть. Это можно проверить: откройте DevTools браузера (вкладка Network).
- Данные вашего аккаунта (токены) хранятся только в вашем браузере (`localStorage`) и отправляются только в DTF и на прокси, который вы выбрали.
- Дополнительные источники получают только запросы, нужные для показа данных. Токен DTF им не передаётся.

## Прокси для входа

DTF не разрешает вход и обновление токена напрямую из стороннего сайта (политика CORS), поэтому нужен прокси: небольшой сервис, который передаёт запрос в DTF и добавляет к ответу разрешающий заголовок. Он ничего не сохраняет. Через прокси проходит пароль (при входе по почте) и токен обновления (при входе по токену и при каждом обновлении сессии).

Способа обойтись без прокси нет. Есть два варианта, чей это прокси:

1. **Свой прокси** (рекомендуется): разворачивается бесплатно на Cloudflare за пару минут, инструкция в [репозитории прокси](https://github.com/re-dtf/proxy). Ваши данные проходят только через ваш сервис.
2. **Прокси автора проекта**, если он включён в этой сборке. Автор не сохраняет данные, но доказать это технически нельзя, поэтому, если не доверяете, используйте свой.

Вход по токену (кука `auth-refresh-remember`) нужен тем, у кого нет пароля, например при входе в DTF через соцсети. Пароль в этом случае не передаётся вообще.

## Что хранится в браузере

- **Настройки** и настройки тем.
- **Сессия DTF** (токены) и токены подключённых источников. Хранятся в открытом виде, как у любого сайта с входом. Если пользуетесь чужим компьютером, выйдите из аккаунта и очистите данные сайта.
- **Подключённые источники** и выданные им разрешения.
- **Копия данных профиля** (имя, аватар) для быстрой загрузки шапки.
